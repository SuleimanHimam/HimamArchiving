# مراسيل · منصّة إدارة الوثائق والمراسلات المؤسسية

**مراسيل (Marasil)** منصّة متكاملة لإدارة الوثائق والأرشفة والمراسلات الداخلية وسير العمل المؤسسي، مصمَّمة باللغة العربية أولًا (واجهة RTL) مع دعم الإنجليزية، وتدعم الوضع الفاتح والداكن. تجمع المنصّة بين إدارة الوثائق الإلكترونية، والأرشيف المادي، والمراسلات (وارد/صادر/داخلي)، والاجتماعات والقرارات، ومحرّك سير عمل قابل للتهيئة، وسجل تدقيق مقاوم للتلاعب — على أساس معماري موحّد.

> الإصدار: Baseline v1.1 — متعدّد المؤسسات (Multi-org ready) · سقف تصميمي 2,000,000 وثيقة.

## نظرة عامة

تغطّي المنصّة دورة حياة كل عنصر (كتاب، وثيقة، قرار) من **الالتقاط ← التسجيل ← التصنيف ← التوجيه ← الاعتماد ← التنفيذ ← الأرشفة**، مع تطبيق الحوكمة (الصلاحيات، التصنيف الأمني، التدقيق، مدد الحفظ) في كل مرحلة.

أبرز المبادئ:
- **المراسلات الداخلية مترابطة:** لا يُنشَأ البريد **الوارد** يدويًا؛ بل يُولَّد تلقائيًا عند إرسال **صادر** إلى موظف أو قسم أو الأرشيف.
- **تصنيف بمحورين مستقلّين:** تصنيف أمني (مَن يطّلع) + تصنيف سجلّي/خطة حفظ (مدّة الاحتفاظ).
- **سجل تدقيق مقاوم للتلاعب:** سلسلة تجزئة (hash chain) متسلسلة، قابلة للتحقّق من سلامتها.
- **معمارية API-first** مع إطار أحداث/Webhooks للتكامل.
- **عربي أولًا + RTL** مع وضع داكن ومظهر قابل للتخصيص.

## التقنيات المستخدمة

| الطبقة | التقنية |
|---|---|
| الواجهة الخلفية | ASP.NET Core Web API — **.NET 10** |
| الوصول للبيانات | **EF Core 10** (موفّر SQL Server وموفّر MySQL) |
| قاعدة البيانات | **SQL Server** 2016+ (بما فيه Express) أو **MySQL 8.4** (`utf8mb4`) — يُختار من `Database:Provider` |
| الأحداث داخل العملية | **MediatR** (Domain Events) |
| المصادقة | **JWT** + **RBAC** (صلاحيات لكل وحدة) + جاهزية MFA (TOTP) |

| التنسيق | **Tailwind CSS v4** + **shadcn/ui** + متغيّرات تصميم مراسيل |
| التدويل | **i18next** (عربي/إنجليزي، RTL/LTR) |
| الحركات | **motion/react** |
| التقارير | QuestPDF (PDF) · مسح ضوئي عبر عميل محلّي (Scan Agent) |

## المعمارية

واجهة خلفية **مقسّمة طبقيًا** (Clean/Layered Architecture):

```
Archiving.Domain          ← الكيانات والـ Enums (نموذج البيانات) + أحداث المجال
Archiving.Application      ← DTOs، واجهات الخدمات، نماذج النتائج/الصفحات
Archiving.Infrastructure   ← EF Core DbContext + Migrations (MySQL)، JWT، التخزين، الخدمات، الخدمات الخلفية
Archiving.Migrations.SqlServer ← Migrations الخاصة بـ SQL Server
Archiving.Api             ← الـ Controllers، حقن التبعيات، الوسطاء (middleware)، سياسات RBAC
```

- **أحداث المجال** تُرسَل بعد الحفظ عبر MediatR (مثل إشعارات/سجلّات).
- **سجل التدقيق** يُكتب عبر `AuditWriter` المركزي (نقطة تحكّم واحدة).
- **خدمات خلفية (Hosted Services):** التصعيد (Escalation)، مدد الحفظ والتصرّف، انتهاء التفويض، لقطات المؤشرات، تسليم الـ Webhooks، التحقّق من سلامة الملفات (Fixity)، استخراج النصوص/OCR.

## الوحدات والميزات

### 1) المصادقة والصلاحيات (Auth / Users / RBAC)
- مستخدمون يُنشئهم المسؤول (لا تسجيل ذاتي)، JWT، جاهزية MFA.
- صلاحيات دقيقة لكل وحدة وإجراء (`Resource.Action`) عبر سمة `[HasPermission]`.

### 2) الهيكل التنظيمي (Organization)
- هيكل متعدّد المستويات (إدارات/أقسام/وحدات)، **الوظائف ككيانات أولى** لدعم التوجيه بالوظيفة لا بالشخص.

### 3) المراسلات (Correspondence) — قسم **المراسلات** الموحّد
- تبويبات **الوارد / الصادر / الداخلي** في سجلّ واحد.
- **توجيه الصادر** إلى: جهة خارجية، أو موظف، أو قسم/إدارة، أو الأرشيف.
- **توليد تلقائي للوارد:** عند اعتماد الصادر وإرساله إلى مستلِم داخلي يظهر تلقائيًا كبريد وارد لديه، مرتبطًا بالكتاب الأصلي.
- **نوع المراسلة:** رسالة نصية أو مستند (رفع ملف أو **مسح ضوئي**)، مع نسخ المرفقات للمستلِم.
- ترقيم تلقائي للكتب، تصنيف سرّية وأولوية، دورة حالة، خط زمني للحركات، إجراءات (إحالة لموظف/قسم، اعتماد، تعليق، إغلاق، أرشفة).

### 4) إدارة الوثائق (Documents)
- **أنواع وثائق ديناميكية + حقول مخصّصة** (يديرها المسؤول دون تعديل الكود).
- مرفقات متعددة، **مسح ضوئي**، تنزيل/معاينة، فهرسة نصّية (OCR) ومتابعة الحالة والموقع المادي.

### 5) الجهات الخارجية (External Directory)
- دليل المنظمات والجهات الخارجية وجهات الاتصال (قابلة للاستخدام كمرسِلين/مستلِمين في المراسلات).

### 6) الاجتماعات والقرارات (Governance)
- **اللجان/المجالس ← الاجتماعات ← المحاضر (جداول الأعمال) ← القرارات الإدارية** (سجل أوّلي دائم غالبًا)، مع ترقيم تلقائي للقرارات ونشرها.

### 7) خطة الحفظ والسجلات (Records / Classification)
- خطة ملفّات هرمية + سلاسل سجلّات تملك قواعد الاحتفاظ، وتصنيف بمحورين (أمني + سجلّي).

### 8) الاحتفاظ والتصرّف (Disposition / Destruction)
- مسار: **تحقّق ← موافقة نهائية ← تنفيذ** للتصرّف (إتلاف/تجديد/ترحيل)، مع **شهادة إتلاف** وتحقّق أمني، و**الحجز القانوني (Legal Hold)** العابر للوحدات.

### 9) الأرشيف المادي والمواقع (Physical Archive)
- تسلسل **المباني ← الغرف ← الخزائن ← الرفوف ← الصناديق** (واجهة بطاقات)، وبطاقات صناديق قابلة للطباعة.

### 10) محرّك سير العمل (Workflow)
- اعتمادات قابلة للتهيئة، توجيه بالشخص/الوظيفة، **التفويض** و**التصعيد** التلقائي وSLA لكل خطوة، مع تدقيق على مستوى الخطوة.

### 11) المهام والمتابعات (Tasks) — وحدة موحّدة للمهام القابلة للإسناد.

### 12) البحث والفهرسة (Search / OCR) — بحث سريع/متقدّم، استخراج نص من PDF/Word + OCR للمستندات الممسوحة.

### 13) لوحات المعلومات والتقارير (Dashboards / Reports)
- مؤشرات تنفيذية وتشغيلية، رسوم بيانية، **تقويم** انتهاء مدد الحفظ، وتقارير قابلة للتصدير (PDF/Excel/CSV).

### 14) سجل المراقبة (Audit)
- سلسلة تجزئة مقاومة للتلاعب وقابلة للتحقّق. **يُسجَّل فقط:** إنشاء/تعديل/حذف/تنزيل/طباعة. حذف السجلّات هو **إخفاء آمن** يحافظ على سلامة السلسلة، مع تسجيل من قام بالحذف.

### 15) التنبيهات (Notifications) — داخل التطبيق وبالبريد (نموذج قنوات قابل للتوسعة).

### 16) التكامل والحفظ طويل الأمد
- **API-first** + أحداث/Webhooks، خطافات تكامل، تسلسلات ترقيم.
- **الحفظ (Preservation):** تحقّق سلامة الملفات (Fixity)، توافق PDF/A، مؤشرات ISO 16363/15489.

### 17) المظهر والهوية (Appearance / Branding)
- تخصيص ألوان الشريط الجانبي وخطّه، وخلفية/لون النظام، ووضع داكن، وشعار/هوية المؤسسة (يظهر في صفحة الدخول والترويسة).

## الأدوار والصلاحيات

أدوار افتراضية: **مدير النظام (System Administrator)**، مدير المؤسسة (Organization Administrator)، مدير إدارة (Department Manager)، مشرف قسم (Section Supervisor)، **موظف (Employee)**، ومدقّق/قراءة فقط (Auditor). لكل دور مجموعة صلاحيات قابلة للتهيئة لكل وحدة/إجراء.

## التشغيل محليًا

> الشرح الكامل، مع حلول المشكلات الشائعة، في
> **[دليل المطوّر: التشغيل محليًا مع SQL Server](docs/local-setup-sqlserver.ar.md)**. فيما يلي الملخّص.

### المتطلبات
- **Windows** 10/11 أو Windows Server (مفاتيح تشفير الملفات تعتمد على DPAPI)
- **.NET 10 SDK**
- **Node.js 22 LTS** (الحد الأدنى 20.19)
- **SQL Server** 2016+ (بما فيه Express) — أو **MySQL 8.4**

### 1) قاعدة البيانات والإعدادات
```powershell
sqlcmd -S .\SQLEXPRESS -E -C -Q "IF DB_ID(N'Archiving') IS NULL CREATE DATABASE [Archiving];"

cd backend\src\Archiving.Api
copy appsettings.Development.SqlServer.json.example appsettings.Development.json
# عدّل فيه: ConnectionStrings:Default و Jwt:Key  (الملف مستثنى من Git — لا ترفعه)
```
لـ MySQL استخدم القالب `appsettings.Development.json.example` بدلًا من ذلك.

### 2) الواجهة الخلفية
```powershell
cd backend
dotnet run --project src/Archiving.Api --launch-profile http   # http://localhost:5105
```
عند أول تشغيل يُنشئ الخادم الجداول ويُدخل البيانات الأولية تلقائيًا، فلا حاجة لـ `dotnet ef database update`.

### 3) الواجهة الأمامية
```powershell
cd frontend
npm install
npm run dev                                     # http://localhost:5173
```
تتصل الواجهة افتراضيًا بـ `http://localhost:5105/api`، ويمكن تغيير ذلك عبر `VITE_API_URL` في `.env.local` (انسخه من `.env.example`).

### 4) الدخول الأول
الواجهة **بالعربية افتراضيًا**. يُنشئ النظام مستخدم مدير عند أول تشغيل:
- **اسم المستخدم:** `admin` (أو `admin@archiving.local`)
- **كلمة المرور:** `Admin@12345`

### الاختبارات
```bash
dotnet test backend/Archiving.slnx
```

## قرارات تصميمية بارزة

- **الوارد لا يُنشأ يدويًا** — يُولَّد من الصادر الداخلي (ترابط كامل بين الطرفين والمرفقات).
- **تصنيف بمحورين** مستقلّين: الأمني (الوصول) والسجلّي (الاحتفاظ).
- **تدقيق مقاوم للتلاعب** بسلسلة تجزئة؛ والحذف إخفاءٌ آمن لا يكسر السلسلة.
- **توجيه بالوظيفة لا بالشخص** — العمل يتبع المقعد الوظيفي فيبقى مستقرًّا عند تغيّر الموظفين.
- **عربي/RTL أولًا** مع وضع داكن متّسق ومظهر قابل للتخصيص لكل متصفّح.
- **API-first** ليتكامل مع الأنظمة والقنوات المستقبلية دون إعادة بناء.
