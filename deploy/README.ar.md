# دليل التنصيب على Windows Server مع SQL Server

الحزمة مجلد واحد يضم الخادم والواجهة وسكربتات التنصيب، وهي **مكتفية ذاتيًا**: لا يحتاج الخادم إلى
تثبيت .NET. خدمة ويندوز واحدة تقدّم الصفحات وواجهة الـ API على منفذ واحد، فلا حاجة إلى IIS أمامها.

النسخة الإنجليزية من هذا الدليل في `README.md` بجانبه، وتحتوي تفاصيل إضافية عن TLS و IIS.

---

## قبل البدء — ما تحتاجه

| | |
|---|---|
| نظام التشغيل | Windows Server 2016 أو أحدث (جُرّب على Windows Server 2025) |
| قاعدة البيانات | SQL Server 2016 أو أحدث — أي إصدار، بما فيه Express (جُرّب على SQL Server 2025) |
| صلاحية | حساب **مسؤول (Administrator)** على الخادم |
| على قاعدة البيانات | صلاحية إنشاء قاعدة بيانات، أو قاعدة جاهزة مسبقًا باسم `Archiving` |
| .NET | **لا يلزم** — الحزمة تحمل ما تحتاجه |

`sqlcmd` غير إلزامي: إن وُجد أنشأ السكربت قاعدة البيانات ومنح الصلاحيات تلقائيًا، وإن لم يوجد
أنشأتَ القاعدة يدويًا من SSMS ثم أعدت تشغيل السكربت.

## الطريقة الأقصر: ملف `Archiving-Setup.exe`

ملف واحد يحمل النظام كاملًا بداخله. **انسخه إلى الخادم وانقر عليه نقرًا مزدوجًا** — يطلب صلاحية
المسؤول، ثم يسأل عن مجلد التنصيب، يفكّ الملفات، **يسجّل خدمة `Archiving` في خدمات ويندوز**، ويفتح
مباشرةً نافذة إعداد الاتصال بـ SQL Server (الموصوفة في الخطوة ٣ أدناه). لا zip تفكّه بيدك، ولا
سكربت تبحث عنه.

- **مجلد التنصيب**: `C:\Archiving` افتراضيًا، وتستطيع اختيار `D:\Archiving` أو غيره.
- **تنصيب سابق في المجلد؟** يحذّرك ويُبقي `appsettings.Production.json` كما هو، فيصلح للتحديث أيضًا.
- **الخدمة**: تُسجَّل باسم `Archiving` وبدء تشغيل مؤجَّل تلقائي، وتبقى **متوقفة** حتى تُكتب إعدادات
  قاعدة البيانات — فلا يُترك الخادم بمجلد ملفات وبلا شيء في `services.msc`. سكربت
  `install-service.ps1` هو ما يكتب الإعدادات ويعيد ضبط الخدمة نفسها ويشغّلها.
- **تنصيب صامت** لعدة خوادم: `Archiving-Setup.exe /S "D:\Archiving"` — يفكّ الملفات ويسجّل الخدمة
  بلا نافذة، ثم تُكمل بـ `install-service.ps1` بمعاملاتها.

بقيّة هذا الدليل تصف الحزمة المضغوطة وسكربتاتها، وهي نفسها الموجودة داخل هذا الملف — فما ينطبق
عليها ينطبق عليه.

## ١ · نسخ الحزمة إلى الخادم

انقل الملف المضغوط `Archiving_<التاريخ>.zip` إلى الخادم (USB، مجلد مشترك، أو عبر جلسة RDP) ثم فك
الضغط في مسار ثابت — `C:\Archiving` أو `D:\Archiving`، كلاهما يعمل.

### التنصيب على قرص D

لا شيء في الحزمة مرتبط بقرص `C`: السكربتات تعمل من المجلد الذي توضع فيه، والخدمة تُسجَّل بمسار
الملف التنفيذي كما هو. ففكّ الضغط في `D:\Archiving` وانقر `Install.cmd` من هناك — هذا كل شيء.

وهو **الترتيب المفضَّل عمليًا**: ضع مجلد الوثائق على `D` أيضًا (`D:\ArchivingData\storage` — وهو
الافتراضي في نافذة التنصيب)، فالوثائق تكبر مع الوقت ولا تريدها تملأ قرص النظام.

ثلاث ملاحظات:

- **يجب أن يكون القرص ثابتًا وداخليًا.** قرص USB أو محرك شبكة مربوط بحرف لا يصلح: الخدمة تبدأ
  قبل أن تُربط محركات الشبكة، فتفشل. إن أردت التخزين على مشاركة شبكية استعمل مسار UNC
  (`\\NAS\Archiving`) واجعل الخدمة تعمل بحساب نطاق يملك صلاحية عليه.
- **لا تضعه داخل مجلد مستخدم** (`C:\Users\…`) — حساب الخدمة لا يصل إليه.
- إن غيّرت مكان المجلد بعد التنصيب: أوقف الخدمة، انقل الملفات، ثم أعد تشغيل `Install.cmd` من
  الموقع الجديد ليُحدَّث مسار الخدمة.

**وماذا عن ملفات قاعدة البيانات نفسها؟** هي شأن SQL Server لا الحزمة، وتُنشأ في المسار الافتراضي
للنسخة. لوضعها على `D` أنشئ القاعدة أولًا من SSMS بالمسار الذي تريده، ثم نصّب — السكربت يستعمل
القاعدة الموجودة ولا ينشئ غيرها:

```sql
CREATE DATABASE [Archiving]
ON PRIMARY (NAME = N'Archiving', FILENAME = N'D:\SQLData\Archiving.mdf')
LOG ON       (NAME = N'Archiving_log', FILENAME = N'D:\SQLData\Archiving_log.ldf');
```

> الملف المضغوط **ليس** ضمن مستودع Git (مجلد `dist/` مستثنى)، فلا يصل إلى الخادم عبر `git pull`.

بعد فك الضغط يجب أن ترى في المجلد: `Archiving.Api.exe` و `install-service.ps1` و `wwwroot`.

## ٢ · الطريقة الأسهل: نقرة مزدوجة على `Install.cmd`

إن لم ترغب في كتابة أوامر، **انقر نقرًا مزدوجًا على `Install.cmd`** داخل المجلد. سيطلب صلاحية
المسؤول (اضغط «نعم») ثم تفتح نافذة التنصيب:

- **خادم SQL Server** — قائمة منسدلة تُعبَّأ تلقائيًا بنسخ SQL Server الموجودة على هذا الجهاز،
  ويمكنك كتابة اسم خادم بعيد بدلًا منها.
- **اسم قاعدة البيانات** — `Archiving` افتراضيًا، وتُنشأ إن لم تكن موجودة.
- **نوع المصادقة** — مصادقة ويندوز (بلا كلمة مرور) أو حساب SQL.
- **مجلد حفظ الوثائق** — مع زر «استعراض…».
- **منفذ الموقع** — `7070` افتراضيًا.
- **زر «اختبار الاتصال»** — يتحقق من الوصول إلى الخادم **قبل** تغيير أي شيء.
- **زر «تنصيب»** — يعرض ملخص الإعدادات للتأكيد، ثم ينفّذ ويعرض السجل في النافذة، وينتهي بعرض
  عنوان الموقع مع عرض بفتحه مباشرة.

هذه النافذة واجهة على `install-service.ps1` نفسه: كل ما تفعله يفعله ذلك السكربت، وهي تكتفي بجمع
الإجابات والتحقق منها وعرض النتيجة. ويندوز لا يوفّر محرّك سكربتات آخر موجودًا على كل خادم، فالمحرّك
تحته PowerShell — لكنك لن تفتح نافذة أوامر ولن تكتب اسم معامل.

**إن فضّلت سطر الأوامر، أو أردت أتمتة التنصيب على عدة خوادم، أكمل بالخطوتين ٣ و ٤ أدناه.**

## ٣ · التنصيب والربط بـ SQL Server

اختر الحالة التي تطابق خادمك:

### أ) SQL Server على نفس الجهاز — مصادقة ويندوز (الأبسط والأكثر أمانًا)

```powershell
.\install-service.ps1 -SqlServer '.\SQLEXPRESS' -Database 'Archiving' `
                      -StoragePath 'D:\ArchivingData\storage'
```

`-SqlServer` هو اسم النسخة (instance): `.` للنسخة الافتراضية، أو `.\SQLEXPRESS`، أو `.\AMEEN10`
— كما يظهر في SSMS. لا تُمرَّر كلمة مرور: الخدمة تتصل بحساب ويندوز الذي تعمل به، والسكربت ينشئ له
تسجيل الدخول ويمنحه `db_owner` على هذه القاعدة وحدها.

### ب) خادم قاعدة بيانات منفصل — بحساب SQL

```powershell
.\install-service.ps1 -SqlServer 'SQL01' -Database 'Archiving' `
                      -SqlUser 'archiving' -SqlPassword 'كلمة-المرور' `
                      -ServiceAccount 'DOMAIN\svc_archiving' `
                      -StoragePath 'D:\ArchivingData\storage'
```

### ج) نسخة مسمّاة أو منفذ غير قياسي

```powershell
.\install-service.ps1 -SqlServer 'SQL01\PROD' -Database 'Archiving' -Port 7070
```

### د) نص اتصال كامل (حالات خاصة)

```powershell
.\install-service.ps1 -ConnectionString 'Server=SQL01,1433;Database=Archiving;User ID=archiving;Password=…;TrustServerCertificate=true;MultipleActiveResultSets=true;'
```

### المعاملات

| المعامل | الافتراضي | المعنى |
|---|---|---|
| `-SqlServer` | `.` | اسم خادم/نسخة SQL Server |
| `-Database` | `Archiving` | اسم قاعدة البيانات — تُنشأ إن لم تكن موجودة |
| `-SqlUser` / `-SqlPassword` | — | حساب SQL؛ اتركهما فارغين لمصادقة ويندوز |
| `-ServiceAccount` | `NT AUTHORITY\NetworkService` | الحساب الذي تعمل به الخدمة |
| `-StoragePath` | داخل مجلد التطبيق | مكان حفظ ملفات الوثائق — **ضعه على قرص فيه سعة للنمو** |
| `-Port` | `7070` | منفذ الموقع |
| `-NoFirewallRule` | — | عدم فتح المنفذ في جدار الحماية |

### ما الذي يفعله السكربت

1. يكتب `appsettings.Production.json` ويولّد **مفتاح توقيع ومفتاح تشفير ملفات جديدين خاصين بهذا
   التنصيب** (لا يُستخدم مفتاح القالب أبدًا).
2. ينشئ قاعدة البيانات إن لم تكن موجودة، وينشئ تسجيل دخول لحساب الخدمة ويمنحه `db_owner` عليها.
3. ينشئ مجلد التخزين ويمنح حساب الخدمة صلاحية الكتابة فيه.
4. يسجّل خدمة ويندوز باسم `Archiving` (تشغيل تلقائي، وإعادة تشغيل عند الفشل).
5. يفتح المنفذ في جدار الحماية ويحجز الـ URL.
6. يشغّل الخدمة وينتظر حتى تستجيب.

**جداول قاعدة البيانات تُنشأ من التطبيق نفسه عند أول تشغيل** (ترحيلات EF)، فلا يوجد ملف SQL
تشغّله يدويًا. تشغيل السكربت مرة أخرى **يحدّث** التنصيب القائم ولا يفشل.

## ٤ · التشغيل بعد التنصيب

**لا يوجد برنامج تفتحه.** النظام خدمة ويندوز تعمل في الخلفية، والسكربت شغّلها بالفعل في نهاية
التنصيب. أنت تستعمله من المتصفّح فقط:

```
http://<اسم-الخادم>:7070/
```

- من الخادم نفسه: `http://localhost:7070/`
- من أي جهاز في الشبكة: `http://اسم-الخادم:7070/` أو `http://192.168.1.x:7070/`
  (لمعرفة عنوان الخادم اكتب `ipconfig` في موجّه الأوامر)

> **غيّرت المنفذ عند التنصيب؟** كل ما في هذا الدليل ينطبق كما هو، فقط استبدل `7070` بمنفذك في
> كل عنوان. المنفذ الذي أدخلته هو ما كُتب في `appsettings.Production.json` وما فُتح في جدار
> الحماية وما حُجز للخدمة — لا يبقى شيء على المنفذ الافتراضي.

**وتعمل تلقائيًا مع تشغيل الخادم** — نوع البدء «تلقائي»، ومضبوطة لإعادة تشغيل نفسها إن توقّفت،
فلا حاجة لأن يسجّل أحد دخوله إلى الخادم لتعمل.

### التحكم بالخدمة من الواجهة الرسومية

اضغط <kbd>Win</kbd>+<kbd>R</kbd> واكتب `services.msc` ثم Enter، وابحث في القائمة عن:

> **Archiving — الديوان الإلكتروني**

بالزر الأيمن عليها: **Start / Stop / Restart**، ومن **Properties** يمكنك تغيير نوع البدء
(Startup type) أو الحساب الذي تعمل به (Log On).

### أو من موجّه الأوامر (cmd) كمسؤول

```cmd
net start Archiving      :: تشغيل
net stop  Archiving      :: إيقاف
sc query  Archiving      :: الحالة
```

### كبرنامج على سطح المكتب

على **الخادم**: يُنشئ التنصيب الاختصار تلقائيًا على سطح المكتب العام (Public Desktop) باسم
**«الديوان الإلكتروني»** وبأيقونة النظام.

على **أجهزة الموظفين**: انسخ إليهم ملفَّي `Create-Desktop-Shortcut.cmd` و `create-shortcut.ps1`
و `app-icon.ico` (أو المجلد كاملًا من مشاركة شبكية)، ثم **نقرة مزدوجة على
`Create-Desktop-Shortcut.cmd`** — يسأل عن عنوان الخادم وينشئ الاختصار. لا يحتاج صلاحية مسؤول.

```powershell
# لكل مستخدمي الجهاز (يحتاج صلاحية مسؤول)
.\create-shortcut.ps1 -Url 'http://SERVER01:7070/' -AllUsers

# نافذة متصفّح عادية بدل نافذة البرنامج
.\create-shortcut.ps1 -Url 'http://SERVER01:7070/' -PlainBrowser
```

الاختصار يفتح النظام **في نافذة مستقلّة بلا شريط عنوان وبلا تبويبات**، بأيقونته الخاصة في شريط
المهام — يشبه أي برنامج مكتبي. تقنيًا هو وضع التطبيق (`--app=`) في Edge أو Chrome، وهو نفس النافذة
التي يعطيها تثبيت تطبيق الويب.

> **ولماذا لا نستعمل زر «تثبيت» داخل النظام؟** لأنه لا يظهر أصلًا على عنوان LAN عبر `http://`
> غير المشفّر — المتصفّحات لا تعرض التثبيت إلا على أصل آمن. فمتى ركّبت شهادة TLS وصار العنوان
> `https://`، سيظهر الزر في أعلى الشاشة وسيصبح التثبيت من داخل النظام أفضل خيار (قائمة ابدأ +
> اختصارات فرعية للديوان والمراسلات والوثائق). حتى ذلك الحين، هذا السكربت يعطيك النتيجة نفسها.

### إن كانت الخدمة لا تعمل

| | |
|---|---|
| الحالة في `services.msc` | يجب أن تكون **Running** |
| سبب التوقّف | `Get-EventLog -LogName Application -Source Archiving -Newest 20` أو من **Event Viewer** ← Windows Logs ← Application |
| تفاصيل أكثر | راجع جدول الأعطال الشائعة في قسم **«إن لم يعمل»** أدناه |

## ٥ · الدخول لأول مرة

### الحسابات المنشأة تلقائيًا

يُنشئ أول تشغيل الأقسام الخمسة التي يأتي بها النظام (الموارد البشرية · المالية · تقنية المعلومات ·
الشؤون الإدارية · قسم الأرشيف) **ومديرًا لكل قسم**، لأن كل قواعد النطاق في النظام مكتوبة بدلالة
قسم والشخص الذي يرأسه.

| الحساب | كلمة المرور |
|---|---|
| `admin` | `Admin@12345` |
| `hr.manager` · `finance.manager` · `it.manager` · `admin.affairs.manager` · `archive.manager` | `Manager@12345` |

> يكفي كتابة الاسم المختصر في خانة الدخول (`admin`)، والعنوان الكامل
> (`admin@archiving.local`) يعمل أيضًا. الاسم المختصر مقبول ما دام يخصّ حسابًا واحدًا فقط.

> ⚠️ **الحسابات الستة نفسها في كل تنصيب**، والخمسة الأخيرة يحملون دور «مدير». غيّر كلمات المرور
> جميعها — أو عطّل من لا تحتاجه منها — قبل أن يصل أحد إلى الخادم. حسابات `demo.*` للتطوير فقط ولا
> تُنشأ في التنصيب الفعلي.

## ٦ · التحقق من نجاح التنصيب

```powershell
# ١. الخدمة تعمل
Get-Service Archiving

# ٢. الموقع يستجيب
Invoke-WebRequest http://127.0.0.1:7070/api/public/stats -UseBasicParsing | Select-Object StatusCode

# ٣. الجداول أُنشئت في قاعدة البيانات (يُتوقع ٨٣ جدولًا و ٧ ترحيلات)
sqlcmd -S '.\SQLEXPRESS' -E -C -d Archiving -Q "SELECT COUNT(*) AS Tables FROM sys.tables; SELECT COUNT(*) AS Migrations FROM __EFMigrationsHistory;"
```

## إن لم يعمل

| العرض | السبب والحل |
|---|---|
| الخدمة تتوقف فور تشغيلها | غالبًا تعذّر الاتصال بقاعدة البيانات. اقرأ السبب: `Get-EventLog -LogName Application -Source Archiving -Newest 20` |
| `Login failed for user 'NT AUTHORITY\NETWORK SERVICE'` | حساب الخدمة لا يملك صلاحية على القاعدة — امنحه `db_owner` من SSMS ثم `Restart-Service Archiving` |
| `A network-related or instance-specific error` | اسم النسخة خطأ، أو بروتوكول TCP/IP معطّل في SQL Server Configuration Manager، أو خدمة `SQL Server Browser` متوقفة (للنسخ المسمّاة) |
| `certificate chain was issued by an authority that is not trusted` | النص يضبط `TrustServerCertificate=true` أصلًا؛ إن غيّرته فأعده أو ثبّت شهادة موثوقة |
| الصفحة لا تفتح من جهاز آخر | جدار الحماية: `New-NetFirewallRule -DisplayName 'Archiving' -Direction Inbound -Protocol TCP -LocalPort 7070 -Action Allow` |
| المنفذ ٧٠٧٠ مشغول | أعد التنصيب بمنفذ آخر: `.\install-service.ps1 -Port 8081 …` |
| IIS يقول `The process cannot access the file because it is being used by another process` | المنفذ محجوز للخدمة في `http.sys`، وإيقاف الخدمة وحده لا يحرّره. لا تشغّل الاثنين على منفذ واحد — راجع القسم التالي |

مسار الإعدادات الذي يمكنك تعديله يدويًا ثم `Restart-Service Archiving`:
`C:\Archiving\appsettings.Production.json`

## برنامج المسح الضوئي على أجهزة الموظفين

المتصفح لا يستطيع مخاطبة ماسح ضوئي موصول بـ USB، فالمسح يمرّ عبر برنامج صغير يعمل على جهاز الموظف.
يأتي داخل الحزمة في `tools\archiving-scan-agent.exe` — ملف تنفيذي واحد مكتفٍ ذاتيًا — والمنصّب يوجّه
النظام إليه، فيصبح متاحًا للتنزيل **من داخل النظام نفسه** عبر `/api/downloads/scan-agent`، لا من رابط
يتناقله الموظفون.

يظهر البرنامج في منطقة التنبيهات، ويمكن ضبطه ليعمل تلقائيًا مع بدء تشغيل ويندوز.

## تشغيل النظام خلف IIS — `Setup-IIS.cmd`

**النظام لا يحتاج IIS.** الخدمة خادم ويب كامل تقدّم الصفحات والـ API معًا. IIS يستحق الإضافة لسبب
واحد: شهادة TLS (‏`https://`) أو اسم نطاق، أو سياسة تُوجب مرور كل الطلبات عبره.

ولا يستطيع IIS تشغيل النظام مباشرة، **ولا مشاركته المنفذ**. إن وجّهت موقعًا إلى منفذ تستخدمه الخدمة
ظهرت رسالة *"used by another process"* — لأن الخدمة تحجز المنفذ في `http.sys`، والحجز لا يزول
بإيقافها. الترتيب الصحيح: **الخدمة على منفذ داخلي مغلق، و IIS على المنفذ العام يمرّر إليها.**

### بنقرة مزدوجة

**`Setup-IIS.cmd`** في مجلد التنصيب. النافذة تفعل كل شيء:

- تفحص IIS و **URL Rewrite** و **ARR**، وتفتح لك صفحة تنزيل الناقص منها
- تفعّل تمرير ARR (‏*Enable proxy*) — وهو مُطفأ افتراضيًا حتى بعد تثبيت ARR
- تنقل الخدمة إلى المنفذ الداخلي (‏`127.0.0.1` فقط) **وتحرّر حجزها على المنفذ العام**
- تنشئ الموقع و‌الـ Application Pool و`web.config` بقاعدة التمرير
- **ترفع حدّ حجم الرفع** من ٣٠ م.ب الافتراضية — وهذا أكثر ما يُعطب أنظمة الأرشفة خلف IIS: كل شيء
  يبدو سليمًا حتى يرفع أحدهم وثيقة أكبر فيحصل على خطأ `404.13` غامض
- تفتح المنفذ في جدار الحماية، ثم **تتحقق أن السلسلة كاملة تستجيب**

وفيها زر **«تراجع»** يزيل موقع IIS ويعيد الخدمة إلى المنفذ العام كما كانت.

### الأخطاء الشائعة بعد الإعداد

| العرض | السبب |
|---|---|
| `502.3` | الخدمة متوقفة أو على منفذ غير الذي في `web.config` |
| `403.14` | قاعدة التمرير لم تُقرأ — تمرير ARR غير مفعّل |
| فشل رفع ملف كبير | حدّ `maxAllowedContentLength` — ارفعه من النافذة |

> **HTTPS:** أضف الشهادة على ربط `443` للموقع في IIS. لاحظ أن النظام لا يقرأ ترويسات `X-Forwarded-*`
> بعد، أي لا يعلم أن الطلب وصل مشفّرًا؛ الواجهة تستخدم مسارات نسبية فلا يظهر أثر ذلك غالبًا.

## التحديث لاحقًا — `Update.cmd`

عند وصول حزمة جديدة، **لا تعيد التنصيب**: فكّ ضغط الحزمة الجديدة في مجلد مؤقّت (مثلًا
`D:\Archiving_new`) ثم **انقر نقرًا مزدوجًا على `Update.cmd` بداخلها**.

يطلب صلاحية المسؤول، ثم:

1. يعرف مكان التنصيب **بسؤال الخدمة نفسها** عن مسارها — فلا تكتب شيئًا في الحالة المعتادة.
2. يقرأ منفذك الفعلي من `appsettings.Production.json` ويعرض ملخّصًا وينتظر تأكيدك.
3. يأخذ نسخة من `appsettings.Production.json` قبل أي شيء.
4. يوقف الخدمة، ينسخ الملفات الجديدة فوق التنصيب، ثم يشغّلها وينتظر حتى تستجيب على منفذك.

### ما لا يمسّه إطلاقًا

- **`appsettings.Production.json`** — نص الاتصال ومفتاح التوقيع ومفتاح تشفير الملفات. مستثنى من
  النسخ صراحةً، ومحفوظة منه نسخة باسم `appsettings.Production.json.bak_<التاريخ>` يمكنك حذفها بعد
  الاطمئنان.
- **مجلد الوثائق وقاعدة البيانات** — التحديث يغيّر البرنامج لا السجلات. ولا يُحذف أي ملف من مجلد
  التنصيب أثناء التحديث، حتى لو كان مجلد التخزين بداخله.

### خيارات

```powershell
.\update-service.ps1 -FullBackup                        # نسخة كاملة من التنصيب الحالي جانبًا
.\update-service.ps1 -TargetPath 'D:\Archiving' -Yes    # مسار صريح وبلا سؤال تأكيد
```

**الترحيلات الجديدة تُطبَّق تلقائيًا عند إقلاع الخدمة**، فلا خطوة إضافية — ولهذا بالذات **خذ نسخة
احتياطية من قاعدة البيانات قبل التحديث** (إعدادات ← النسخ الاحتياطي، أو `BACKUP DATABASE` من SSMS).

إن لم تستجب الخدمة خلال دقيقتين يخبرك السكربت ويترك نسخة الإعدادات في مكانها، والسبب يظهر في
Event Viewer ← Windows Logs ← Application.

## الإزالة — `Uninstall.cmd`

من **مجلد التنصيب** (لا من حزمة جديدة): **نقرة مزدوجة على `Uninstall.cmd`** ← «نعم» لطلب
الصلاحية ← `y` للتأكيد.

### ما يُزيله

- خدمة ويندوز `Archiving`
- قاعدة جدار الحماية وحجز العنوان **على منفذك الفعلي** (يقرأه من `appsettings.Production.json`)
- اختصار سطح المكتب — العام واختصار المستخدم الحالي

### ما يُبقيه — عمدًا

**قاعدة البيانات والوثائق وملف الإعدادات.** حذف أرشيف وثائق ليس شيئًا يقرّره سكربت من تلقاء نفسه،
فبدل ذلك يطبع لك في النهاية أين تقع الثلاثة بالضبط — بأسمائها ومساراتها الحقيقية المقروءة من
إعداداتك — لتحذف ما تريد بنفسك:

```
  1. الوثائق:       D:\ArchivingData\storage
  2. قاعدة البيانات: [Archiving] on .\AMEEN10
        DROP DATABASE [Archiving];   -- من SSMS، بعد أخذ نسخة احتياطية
  3. هذا المجلد:     D:\Archiving
```

> ⚠️ مجلد التنصيب يحوي `appsettings.Production.json`، وفيه **مفتاح فك تشفير الوثائق المخزَّنة**.
> إن حذفته ثم استعدت نسخة احتياطية لاحقًا، فلن تُفتح المرفقات. احتفظ بنسخة منه قبل الحذف.

وأجهزة الموظفين تحتفظ باختصاراتها — تُحذف يدويًا على كل جهاز.

### الحذف الكامل — `Remove-Everything.cmd`

إن أردت **حذف كل شيء فعلًا** — الوثائق وقاعدة البيانات ومجلد التنصيب — فذلك ملف منفصل باسم
صريح: **`Remove-Everything.cmd`**، بجانب `Uninstall.cmd` في مجلد التنصيب.

```
  الوثائق         → تُحذف من القرص
  قاعدة البيانات   → تُسقَط (DROP DATABASE)
  مجلد التنصيب    → يُحذف
```

**لا تراجع.** لذلك قبل أن يمسّ شيئًا يعرض لك المسارات الحقيقية الثلاثة، ثم يطلب منك **كتابة اسم
قاعدة البيانات** بيدك. أي شيء غير الاسم الصحيح يُلغي العملية ولا يُحذف شيء. ولا يوجد خيار يتخطّى
هذا السؤال — لا `-Yes` ولا غيره — لأن مسارًا مدمّرًا يمكن تجاوزه بخيار سيُنفَّذ يومًا بالخطأ.

الترتيب: يوقف الخدمة ويزيلها أولًا (وإلا لبقيت تمسك الملفات وقاعدة البيانات)، ثم يحذف الوثائق،
ثم يُسقط القاعدة بعد `SINGLE_USER` — لأن أي اتصال مفتوح، ولو نافذة SSMS مفتوحة عندك، يمنع
الإسقاط. ومجلد التنصيب يُحذف بعد ثوانٍ من إغلاق النافذة، لأن السكربت لا يستطيع حذف المجلد الذي
يعمل من داخله.

> **قبل التنفيذ:** احتفظ بنسخة من `appsettings.Production.json` إن كان هناك احتمال أن تستعيد
> نسخة احتياطية لاحقًا — فيه مفتاح فك تشفير الوثائق، وبدونه لا تُفتح المرفقات المستعادة.

من سطر الأوامر: `.\uninstall-service.ps1 -RemoveAll`

### إعادة التنصيب بعد الإزالة

القاعدة والوثائق ما زالت مكانها، فتشغيل `Install.cmd` من جديد بنفس الإعدادات يعيد النظام كما كان
ببياناته كاملة.

### من سطر الأوامر

```powershell
.\uninstall-service.ps1          # مع سؤال تأكيد
.\uninstall-service.ps1 -Yes     # بلا سؤال
```

## ملحق · التنصيب اليدوي بالكامل (بلا أي سكربت)

إن كانت سياسة الخادم تمنع تشغيل السكربتات، الخطوات الخمس التي يقوم بها السكربت يمكن أداؤها يدويًا:

**١. أنشئ قاعدة البيانات** من SQL Server Management Studio:

```sql
CREATE DATABASE [Archiving];
GO
-- امنح حساب الخدمة صلاحية (مع مصادقة ويندوز)
CREATE LOGIN [NT AUTHORITY\NetworkService] FROM WINDOWS;
USE [Archiving];
CREATE USER [NT AUTHORITY\NetworkService] FOR LOGIN [NT AUTHORITY\NetworkService];
ALTER ROLE db_owner ADD MEMBER [NT AUTHORITY\NetworkService];
```

**٢. أنشئ ملف الإعدادات**: انسخ `appsettings.Production.json.template` باسم
`appsettings.Production.json` وافتحه بالمفكرة (Notepad)، ثم عدّل:

```json
{
  "ConnectionStrings": { "Default": "Server=.\\SQLEXPRESS;Database=Archiving;Integrated Security=true;TrustServerCertificate=true;MultipleActiveResultSets=true;" },
  "Database": { "Provider": "SqlServer" },
  "Urls": "http://0.0.0.0:7070",
  "Jwt": { "Key": "ضع هنا نصًا عشوائيًا طويلًا لا يقل عن ٣٢ حرفًا" },
  "Storage": { "RootPath": "D:\\ArchivingData\\storage", "EncryptionKey": "" }
}
```

> `Jwt:Key` **يجب** أن يكون خاصًا بهذا الخادم — مفتاح مشترك يعني أن من يملك الحزمة يستطيع إصدار
> رمز دخول صالح. اترك `Storage:EncryptionKey` فارغًا لتخزين الملفات دون تشفير، أو ضع ٣٢ بايت
> بترميز Base64 لتشفيرها — واحتفظ بنسخة من المفتاح، فبدونه لا تُفتح الملفات.

**٣. جرّب التشغيل أولًا**: انقر نقرًا مزدوجًا على `Archiving.Api.exe`. تفتح نافذة سوداء وتُنشأ
الجداول؛ افتح `http://localhost:7070/` للتأكد، ثم أغلق النافذة.

**٤. سجّل الخدمة** من موجّه الأوامر (cmd) كمسؤول:

```cmd
sc create Archiving binPath= "C:\Archiving\Archiving.Api.exe" start= auto obj= "NT AUTHORITY\NetworkService"
sc failure Archiving reset= 86400 actions= restart/5000/restart/10000/restart/30000
netsh http add urlacl url=http://+:7070/ user="NT AUTHORITY\NetworkService"
sc start Archiving
```

**٥. افتح المنفذ في جدار الحماية**: لوحة التحكم ← Windows Defender Firewall ← Advanced Settings ←
Inbound Rules ← New Rule ← Port ← TCP ← 7070 ← Allow.

وتأكّد أن حساب الخدمة يملك صلاحية القراءة على `C:\Archiving` والكتابة على مجلد التخزين
(خصائص المجلد ← Security).

## النسخ الاحتياطي

من داخل النظام: **إعدادات ← النسخ الاحتياطي**. على SQL Server يُنفَّذ `BACKUP DATABASE … WITH
COPY_ONLY`، والملف يكتبه محرك SQL Server نفسه بهوية حساب خدمته وعلى نظام ملفات خادم قاعدة
البيانات — فيجب أن يكون المجلد قابلًا للكتابة من SQL Server وللقراءة من التطبيق.

> **خُذ نسخة من مجلد التخزين أيضًا.** الوثائق تُحفظ على القرص مشفّرة، وقاعدة البيانات لا تحمل سوى
> بياناتها الوصفية: نسخة القاعدة وحدها تعيد فهرسًا لملفات لا يمكن فتحها.
> واحتفظ بنسخة من `appsettings.Production.json` في مكان آمن — فيه مفتاح فك تشفير الملفات، وبدونه
> لا تُفتح المرفقات المستعادة.

## ملاحظة عن نقل قاعدة بيانات قائمة

لكل محرّك (MySQL / SQL Server) سجل ترحيلات خاص به، والمخططان مولّدان من النموذج نفسه لكنهما ليسا
SQL متبادلًا. لذلك **لا يمكن نقل التنصيب من MySQL إلى SQL Server بنسخ نسخة احتياطية**؛ النقل يتم
بترحيل البيانات (SSMA for MySQL أو تصدير/استيراد).
